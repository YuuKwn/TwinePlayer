# Native Save/Load experience — UX Preview 5

2026-10-18. Build `20261018-ux5`; product `0.9.0-phase9-test-ux5`. Follow-up to SAVE-DIALOG-INVESTIGATION.md. Previous packages remain available.

## What changed

- App Load opens the native manager directly; no SugarCube Saves window or pending engine file input is constructed. Canceling returns to the story. The Load manager includes **Create a new save…**.
- Save invokes the engine's disk routine and captures its original bytes: modern SC2 `Save.disk.save`, older SC2 `Save.export`, SC1 `SaveSystem.exportSave`. This preserves disk-specific game callbacks and restrictions. The old SC2 export-with-no-return-value failure is fixed.
- Load supplies an in-memory file to the matching engine routine. Modern loads await the engine Promise; legacy loads observe the engine's own FileReader and require actual restored state. Invalid/foreign saves remain rejected; the engine still validates its format, ID and callbacks. No raw state replacement or browser-save-bundle fallback is used.
- Errors generated by these operations appear in native UI. Legacy save-error dialogs are temporarily suppressed for that operation, closed and cleaned up. SC1 overlay animation queues are finished so an invisible layer cannot block story clicks. Unrelated game dialogs remain available; an existing game prompt must be closed before beginning an engine save/load operation.
- Native-only browser hooks install before story scripts can cache file/download methods. Save file-input clicks, associated labels, `showPicker`, and the standard SC1/SC2 Saves menu route into native UI. Blob exports are captured before browser download UI. Native browser/page Save As requests are canceled and routed to app Save; unsolicited downloads remain canceled with default UI handled.
- Capture/restore messages correlate to their operation. Timeout, cancellation and document changes clean up temporary operation state; late correlated results do not open another manager.
- Sidebar states and opaque console from Preview 4 remain. Save locations, filename validation, overwrite/delete confirmation, 50 MiB limits and durable atomic writes are unchanged. Flutter/shared bridge and WPF source are untouched.

## Verification

Locked restore, zero-warning Release build and 58 unit tests pass, including capture correlation/source validation. Genuine-engine DOM checks cover SC1 1.0.35, SC2 2.18.0, Accidental Mind SC2 2.36.1 and authored SC2 2.37.3: first/repeated roundtrips, invalid-save retry, foreign-save rejection, engine-denied saves, cleanup, unrelated prompts and file-input/label/showPicker routing. Final report and actual native/package checks are recorded in EXECUTION.md.

The native WebView2 suite uses fresh disposable profiles and copied games. It exercises the real Load dialog, cancel, Create a new save, canceled Save, first/repeated disk writes and restores, invalid-save native error/retry, cleanup, all picker/menu entry points and real browser Save As suppression. A test-only CDP guard counts and fails any unexpected file-picker request; production uses the early browser hooks, not that guard. Existing native real-game/Flutter save compatibility, runtime and XAML suites remain required.

Coverage is for the listed genuine engines and standard entry points. Arbitrary custom save menus and browser-save bundles are not newly supported. No physical/client/screen-reader/compositor certification is inferred from programmatic tests. Private game files and saves are excluded from packages.

## Try the build

Extract the whole ZIP and run TwinePlayer.Native.exe. Confirm **UX Preview 5** in the title bar. On first use, try Save, Load and the game's standard Saves entry; only the app's manager should appear. Cancel, retry, and load an existing compatible save. The Load manager's Create a new save action switches to Save. Existing sidecar saves stay beside the game in its `_saves` directory.
